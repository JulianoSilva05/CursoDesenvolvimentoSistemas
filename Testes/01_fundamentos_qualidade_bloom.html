PARTE 1 — Explicação (1 hora)

1. O que é Qualidade de Software?

Explique assim: Qualidade de software é garantir que um sistema funcione corretamente, tenha poucos erros, seja fácil de usar, seguro e atenda ao que o usuário precisa.

Ideia central

Um software de qualidade não é apenas “um programa que abre”. Ele precisa:

  • funcionar corretamente;
  • entregar o resultado esperado;
  • evitar falhas;
  • ser confiável;
  • ser fácil de usar;
  • proteger dados;
  • ter boa organização.

Exemplos práticos

  • sistema trava ao clicar em salvar → sem qualidade;
  • login não funciona → sem qualidade;
  • cálculo de preço sai errado → sem qualidade;
  • sistema lento demais → sem qualidade;
  • usuário não entende os botões → sem qualidade;
  • sistema funciona corretamente, com clareza e segurança → qualidade.

2. O que é QA?

QA significa Quality Assurance, ou Garantia da Qualidade.

QA não é apenas testar no final. QA é o processo de garantir qualidade desde o início do desenvolvimento.

Diferença importante

  • Testador/Tester: executa testes e encontra erros.
  • QA: pensa no processo inteiro para evitar erros, melhorar a qualidade e validar o sistema.

Frase forte para usar em aula: QA não existe só para achar erro. QA existe para evitar que o erro chegue ao usuário.

3. Os 4 pilares da qualidade

1. Funcionalidade — O sistema faz o que deveria fazer? Ex.: ao cadastrar produto, ele salva corretamente?

2. Performance — O sistema é rápido e responde bem? Ex.: a tela demora 20 segundos para carregar.

3. Segurança — Os dados estão protegidos? Ex.: o sistema aceita código malicioso digitado pelo usuário.

4. Usabilidade — É fácil de usar? Ex.: botões mal posicionados, mensagens confusas, usuário não entende o que aconteceu.

4. O que é bug?

Bug é qualquer comportamento incorreto, inesperado ou inadequado no sistema.

Exemplos

  • botão não funciona;
  • cálculo errado;
  • sistema fecha sozinho;
  • permite cadastrar dados inválidos;
  • mostra sucesso mesmo com erro;
  • aceita entrada indevida.

5. Mentalidade QA

Um bom QA pensa assim:

  • e se o usuário deixar vazio?
  • e se ele digitar texto no lugar de número?
  • e se ele digitar valor negativo?
  • e se clicar várias vezes?
  • e se tentar quebrar o sistema?
  • e se os dados vierem errados?

Frase para reforço: Um bom QA não testa apenas o caminho bonito. Ele testa principalmente o caminho do erro.

6. Ciclo de teste

Fluxo simples:

  1. o desenvolvedor cria o sistema;
  2. o QA testa;
  3. se encontrar erro, registra o bug;
  4. o desenvolvedor corrige;
  5. o QA testa novamente;
  6. se estiver correto, valida a correção.

PARTE 2 — Bugs na prática (Python) 1/2

Agora comparativos entre código errado e correto, com explicação e teste.

Exemplo 1 — Erro clássico de validação

Situação: verificar se o nome está vazio.

Código errado

nome = input("Digite o nome do produto: ")

if nome == " ":
    print("Nome obrigatório")

Problema: compara com um espaço, não com vazio real. Se o usuário apertar Enter, a string será "" e a validação falha.

Código correto

nome = input("Digite o nome do produto: ")

if nome == "":
    print("Nome obrigatório")

Melhor ainda

nome = input("Digite o nome do produto: ")

if nome.strip() == "":
    print("Nome obrigatório")

Por que .strip()? Remove espaços do começo e do fim: "" e " " viram vazio tratado.

Como testar: (1) Enter sem nada → “Nome obrigatório”; (2) só espaços → “Nome obrigatório”; (3) “Bicicleta” → aceita. Tipo de bug: Funcional.

Exemplo 2 — Validação incompleta de número

preco = input("Digite o preço: ")

if float(preco) < 0:
    print("Preço inválido")

Problemas: quebra com vazio, letras, símbolos ("", "abc", "dez").

preco = input("Digite o preço: ")

if preco.strip() == "":
    print("Preço inválido")
else:
    try:
        valor_preco = float(preco)
        if valor_preco < 0:
            print("Preço inválido")
    except ValueError:
        print("Preço inválido")
EntradaResultado esperado
""erro
"abc"erro
-10erro
100válido

Tipo de bug: Validação / regra de negócio.

Exemplo 3 — Mensagem de sucesso mesmo com erro

nome = input("Digite o nome: ")

if nome.strip() == "":
    print("Nome obrigatório")

print("Produto cadastrado com sucesso")

Problema: mesmo com nome vazio, mostra sucesso depois do erro — confunde o usuário.

nome = input("Digite o nome: ")

if nome.strip() == "":
    print("Nome obrigatório")
else:
    print("Produto cadastrado com sucesso")

Tipo de bug: Usabilidade e lógica.

Exemplo 4 — Falta de segurança (conceito)

nome = input("Digite o nome do produto: ")
print("Produto:", nome)

Em contexto web, entrada como <script>alert('hack')</script> seria perigosa. No terminal só aparece texto, mas o conceito importa.

import html

nome = input("Digite o nome do produto: ")
nome_seguro = html.escape(nome)

print("Produto:", nome_seguro)

Tipo de bug: Segurança.

Exemplo 6 — Cálculo errado

preco = 100
quantidade = 3

print(total)

Correto: total = preco * quantidade → 300. Tipo: Funcional / regra de negócio.

Exemplo 7 — Falta de tratamento de exceção

print(numero)

try:
    numero = int(entrada)
    print(numero)
except ValueError:
    print("Valor inválido")

Tipo de bug: Robustez / validação.

PARTE 4 — Aplicar testes no código

def validar_nome(nome):
    if nome.strip() == "":
        return "Nome obrigatório"
    return "Nome válido"
print(validar_nome(""))
print(validar_nome("   "))
print(validar_nome("Bicicleta"))
def validar_preco(preco):
    if str(preco).strip() == "":
        return "Preço inválido"
    try:
        valor = float(preco)
        if valor < 0:
            return "Preço inválido"
        return "Preço válido"
    except ValueError:
        return "Preço inválido"
def validar_idade(idade):
    if idade < 18:
        return "Menor de idade"
    return "Maior de idade"

assert validar_idade(15) == "Menor de idade"
assert validar_idade(18) == "Maior de idade"
assert validar_idade(25) == "Maior de idade"

print("Todos os testes passaram com sucesso.")

assert verifica se o resultado está correto; se não estiver, o Python acusa falha.

PARTE 6 — Versão melhor organizada em funções

                
def validar_nome(nome):
    if nome.strip() == "":
        return False, "Nome obrigatório"
    return True, ""


def validar_preco(preco):
    try:
        valor = float(preco)
        if valor < 0:
            return False, "Preço inválido"
        return True, valor
    except ValueError:
        return False, "Preço inválido"


def validar_quantidade(quantidade):
    try:
        valor = int(quantidade)
        if valor <= 0:
            return False, "Quantidade inválida"
        return True, valor
    except ValueError:
        return False, "Quantidade inválida"


nome = input("Digite o nome do produto: ")
preco = input("Digite o preço do produto: ")
quantidade = input("Digite a quantidade: ")

erro = False

nome_ok, msg_nome = validar_nome(nome)
if not nome_ok:
    print(msg_nome)
    erro = True

preco_ok, resultado_preco = validar_preco(preco)
if not preco_ok:
    print(resultado_preco)
    erro = True
else:
    valor_preco = resultado_preco

quantidade_ok, resultado_quantidade = validar_quantidade(quantidade)
if not quantidade_ok:
    print(resultado_quantidade)
    erro = True
else:
    valor_quantidade = resultado_quantidade

if not erro:
    total = valor_preco * valor_quantidade
    print("Total:", total)
    print("Produto cadastrado com sucesso")

PARTE 10 — Frases de fechamento

                
    
                    
  • Software com qualidade não é o que parece bonito. É o que funciona corretamente para o usuário.
    • 
                    
  • Testar não é “procurar defeito por maldade”. É proteger o usuário de falhas.
    • 
                    
  • Um erro que chega no usuário mostra que a qualidade falhou em algum ponto do processo.
    • 
                    
  • QA não é só achar erro. É pensar antes, testar durante e validar depois.
    • 
                    
  • O bom profissional não apenas escreve código. Ele garante que o código funcione bem.
