Aula 02: Requisitos e Casos de Teste

Aula 02
RF • Critérios de Aceitação • Cenários

Objetivo

Aprender a transformar requisitos (RF) em casos de teste completos, com:

  • pré-condições
  • dados de teste
  • passos
  • resultado esperado
  • evidência

Regra de ouro: se o caso de teste não pode ser repetido por outra pessoa, ele está incompleto.

Taxonomia de Bloom nesta aula

Foco em Entender (o que é critério de aceite) e Aplicar (preencher casos de teste com dados e passos reproduzíveis).

  • Você transforma linguagem de negócio em verificações objetivas.
  • Cada caso deve ser executável por outra pessoa sem te perguntar “e agora?”.

Conecte com UML: caso de uso e requisitos que vocês já modelaram viram a fonte dos cenários de teste.

Estrutura de um Caso de Teste (modelo)

CTxx - Título
Requisito(s): RFxx
Prioridade: Alta/Média/Baixa
Pré-condições: ...
Dados: ...
Passos:
  1) ...
  2) ...
Resultado esperado: ...
Evidência: print / log / vídeo / registro

Critérios de Aceitação: o que define “passou”

Boas práticas

  • Seja mensurável (“mensagem X aparece”).
  • Evite subjetivo (“ficou bom”).
  • Inclua sucesso e erro.
  • Inclua validações.

Exemplo

RF: cadastrar produto

Aceitação: ao enviar com campos válidos, sistema salva e mostra confirmação com o nome do produto.

Atividade 1: RF → Casos de Teste completos

⚠️ Atividade INDIVIDUAL. Use “Dividir Tela” para consultar o material.

Enunciado

Crie 4 requisitos funcionais para um sistema de “Cadastro de Produtos” e escreva 1 caso de teste completo para cada RF.

Obrigatório

  • 2 casos de sucesso
  • 2 casos de erro/validação
  • Dados de teste explícitos
  • Resultado esperado verificável

Atividade 2: Priorização (risco x impacto)

Enunciado

Escolha 6 casos de teste (pode usar os seus) e classifique prioridade (Alta/Média/Baixa) justificando com risco/impacto.

Dica

Alta prioridade normalmente é: dinheiro, segurança, dados, login, persistência, regras críticas.

Encerramento

Na próxima aula: técnicas de teste (particionamento, valor-limite) para criar dados e coberturas mais inteligentes.
