Tipos de sensores (com exemplos)

Analógicos

  • LDR (luz)
  • Potenciômetro (posição)
  • Sensor de umidade do solo (varia resistência/capacitância)

Você lê um valor (ex: 0–1023) e converte para uma unidade.

Digitais

  • Botão (0/1)
  • Sensor de presença (PIR)
  • Sensores com protocolo (ex: I2C/1‑Wire)

Você lê estados ou pacotes de dados com maior estabilidade.

Armadilha comum: achar que “0–1023” é linear e equivalente em qualquer placa. Considere tensão de referência, divisor resistivo e ruído.

Características técnicas que importam

Conceitos

  • Faixa: min–máx que o sensor mede
  • Resolução: “granularidade” do valor
  • Precisão: quão perto do valor real
  • Tempo de resposta: velocidade da leitura

Exemplo prático

Sensor de temperatura pode oscilar 0.2–0.5°C por ruído. Se você aciona um relé quando TEMP > 25, ele pode ficar ligando/desligando rápido.

Solução: aplicar média móvel e histerese (ex: liga em 25.5, desliga em 24.5).

Calibração e validação (exemplos práticos)

Calibração (dois pontos)

Para um sensor analógico, você pode calibrar com dois pontos e ajustar uma reta:

valorCalibrado = a * leitura + b Exemplo: em 0°C a leitura média foi 120 em 50°C a leitura média foi 820

Validação (regras simples)

  • Faixa válida (ex: 0–60°C)
  • Variação máxima por segundo (ex: não “pula” 20°C de uma vez)
  • Condição de erro (ex: leitura nula repetida)
if temp < 0 or temp > 60 then marcar ERRO if abs(temp - tempAnterior) > 5 then suspeita (outlier)

Regra de segurança: em caso de erro, o sistema deve entrar em modo seguro (ex: desligar atuador) e alertar.

Filtragem: média móvel e histerese

Média móvel (reduz ruído)

Guarde os últimos N valores e faça a média. Isso estabiliza a leitura.

add leitura na lista historico se lista > 10, remove o mais antigo media = soma(historico) / tamanho(historico)

Histerese (evita “piscar”)

Defina dois limiares: ligar e desligar.

if (estado = DESLIGADO) and (media >= 25.5) then LIGAR if (estado = LIGADO) and (media <= 24.5) then DESLIGAR

Projetar com intenção: escolher N grande demais deixa o sistema lento; N pequeno não filtra. Teste e registre.

Formato de telemetria (padrão recomendado)

Texto simples (depuração rápida)

TS:1712345678;TEMP:26.3;HUM:62;LDR:812;ERR:0\n

Inclua timestamp e um flag de erro.

JSON (quando for para nuvem)

{"ts":1712345678,"temp":26.3,"hum":62,"ldr":812,"err":0}

JSON é ótimo para APIs, mas exige mais parsing. Use quando fizer sentido.

Atividade 1 (4h): Plano de medição e validação

⚠️ Importante: Atividade INDIVIDUAL. Não saia desta tela. Entregue pelo botão de envio.

Cenário

Você vai monitorar a temperatura de uma sala e acionar um ventilador (atuador).

  • Faixa esperada: 15–40°C
  • Leitura a cada 2s
  • Ventilador liga acima de um limite

Produza

  • Regras de validação (faixa, variação, erro)
  • Estratégia de filtragem (N e justificativa)
  • Histerese (limiar de liga/desliga)
  • Formato de telemetria (texto ou JSON)

Atividade 2 (4h): Implementar regra de alerta no app

Entrada simulada

Use um botão “Nova Leitura” que gera valores aleatórios para simular o sensor, ou use dados recebidos por Bluetooth.

  • Guardar histórico

  • Aplicar histerese

Checklist

  • Mostra “OK”/“ALERTA” e muda cor
  • Não fica alternando sem parar (histerese)
  • Se valor inválido, registra e ignora
  • Persistência do limite no TinyDB
