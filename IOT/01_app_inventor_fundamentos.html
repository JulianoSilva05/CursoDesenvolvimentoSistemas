O que é IoT (na prática)

Definição prática

IoT é quando um dispositivo (sensor/atuador) coleta dados ou executa ações e se integra com um software (app/servidor/nuvem) por meio de uma rede.

Exemplos reais: monitorar temperatura, acionar uma lâmpada, rastrear consumo, enviar alertas.

Componentes de um sistema IoT

  • Coleta: sensores (temperatura, luz, presença, aceleração).
  • Processamento: microcontrolador (Arduino/ESP32) ou o próprio celular.
  • Comunicação: Bluetooth / Wi‑Fi / Internet.
  • Aplicação: app, dashboard, automação e alertas.

App Inventor: visão geral (Designer x Blocks)

O App Inventor tem duas áreas principais:

  • Designer: monta a interface (telas, botões, imagens, listas).
  • Blocks Editor: programa o comportamento (eventos, lógica, dados, sensores).

Dica prática

Comece sempre pelo Designer com uma UI simples, depois programe apenas um evento por vez (clicar, mudar texto, registrar valor).

Regra de ouro

Se algo não funciona, confirme na ordem: componente certo → evento certo → dados certos → resultado visível.

Primeiro acesso e ambiente de trabalho

Acessar o App Inventor

  • Abra ai2.appinventor.mit.edu no navegador.
  • Faça login com conta Google (pessoal ou institucional).
  • Menu Projects → Start a New Project.
  • Escolha um nome curto (ex.: HelloIoT).

Se o site pedir permissões, aceite. Mantenha o navegador atualizado.

Organização do ambiente

  • Designer: constrói a interface (telas e componentes).
  • Blocks: implementa a lógica (eventos e ações).
  • Palette: lista de componentes; Viewer: área de montagem; Properties: configurações.
  • Non-visible: componentes que não aparecem (Web, TinyDB, BluetoothClient).

Testes no celular (MIT AI2 Companion) e emulador

Companion (Android/iOS)

  1. No celular, instale MIT AI2 Companion (loja oficial).
  2. No App Inventor (navegador), clique Connect → AI Companion.
  3. Abra o Companion no celular e escaneie o QR Code exibido.
  4. O app do celular carregará seu projeto automaticamente em tempo real.

Celular e PC devem estar na mesma rede (Wi‑Fi). Se sua escola bloquear, use cabo ou o emulador.

Emulador (PC)

  1. Baixe e instale o App Inventor Setup (em “Setup Instructions”).
  2. No App Inventor, clique Connect → Emulator.
  3. Aguarde a inicialização; o projeto abre em uma janela de Android.
  4. Use o emulador quando não há celular disponível ou rede restrita.

O emulador é mais lento que o celular. Para sensores, prefira testar no dispositivo real.

Componentes, eventos, métodos e propriedades

O que é o quê

  • Componente: “peça” do app (Button, Label, ListView, Web, BluetoothClient).
  • Evento: algo acontece (Button.Click, Clock.Timer, Web.GotText).
  • Método: ação (call Web.Get, call TinyDB.StoreValue).
  • Propriedade: configuração (Button.Text, Label.Visible, Clock.TimerInterval).

Exemplo rápido

when ButtonEnviar.Click do set LabelStatus.Text to "Enviando..." call Web1.Get when Web1.GotText do set LabelStatus.Text to "OK!"

Isso já é um “mini IoT”: o app dispara uma requisição e reage ao retorno.

Variáveis, procedimentos e listas (padrões úteis)

Variáveis (estado do app)

  • estadoConexao (conectado/desconectado)
  • ultimoValor (telemetria mais recente)
  • limiteAlerta (configuração do usuário)

Em IoT, variáveis viram o seu “painel”: elas mostram o que está acontecendo agora.

Procedimentos (reuso)

  • AtualizarUI() para trocar textos e cores.
  • ValidarNumero(texto) para evitar erro.
  • RegistrarLog(msg) para depuração.

Procedimentos deixam seu app robusto e fácil de manter.

Listas (telemetria e histórico)

Uma lista pode guardar os últimos N valores do sensor para fazer gráfico, média ou detectar picos.

append to list historicoValores item ultimoValor if length of list historicoValores > 20 remove list item list historicoValores index 1

Checklist de qualidade

  • Nomeie variáveis com intenção (sem “x”, “temp”).
  • Valide entradas do usuário (vazio, não numérico).
  • Mostre feedback na tela (status, cor, ícone).

Persistência com TinyDB (salvar configurações)

Quando usar

  • Salvar limite de alerta (temperatura máxima).
  • Salvar nome do dispositivo ou endereço Bluetooth.
  • Guardar preferências de tela do usuário.

Padrão recomendado

when Screen1.Initialize do set limiteAlerta to call TinyDB1.GetValue(tag="limite", valueIfTagNotThere=30) set TextBoxLimite.Text to limiteAlerta when ButtonSalvar.Click do call TinyDB1.StoreValue(tag="limite", value=TextBoxLimite.Text)

Resultado: o app “lembra” do limite mesmo após fechar.

Exemplo guiado: Painel “Smart Home” (UI + estado)

Designer (passo a passo)

  1. Crie um projeto: SmartHomePainel.
  2. Adicione um VerticalArrangement (Width: Fill Parent).
  3. Coloque um Label para o título e um Label para status.
  4. Adicione 3 botões: LED, Ventilador, Portão.
  5. Adicione um ListView para “Logs” (ou um Label grande).
  6. Adicione um TinyDB (não visível).

Blocks (lógica mínima)

  1. Crie variável log como lista vazia.
  2. Crie procedimento Registrar(msg) que adiciona no log e atualiza o ListView.
  3. No click de cada botão, altere o texto do status e registre no log.
  4. Salve no TinyDB o último estado dos botões.
to Registrar(msg) add items to list log item (join Clock1.Now " - " msg) set ListViewLogs.Elements to log

Por que isso é IoT? Antes de falar com sensores reais, você precisa dominar: interface, estado, validação e registro. IoT é integração, e integração começa pela qualidade do app.

Atividade 1 (4h): “Hello IoT” com validação e log

⚠️ Importante: Atividade INDIVIDUAL. Não saia desta tela. Entregue pelo botão de envio.

  • Guardar histórico com no máximo 20 eventos.
  • Botão “Limpar Log”.

Atividade 2 (4h): Mini-dashboard local com TinyDB

Cenário

Você está criando um painel para monitorar um sensor (a leitura será simulada por enquanto). O usuário define um limite e o app registra leituras.

  • TextBox: limite
  • Botão: “Salvar limite”
  • Botão: “Nova leitura” (gera número aleatório)
  • Label: leitura atual
  • Lista: histórico

Regras

  • Se leitura > limite, mostrar alerta visual (cor/ícone) e registrar no log.
  • Salvar limite e histórico no TinyDB.
  • Ao abrir o app, restaurar os dados e atualizar a tela.
set leitura to random integer from 0 to 60 if leitura > limiteAlerta set LabelStatus.Text to "ALERTA" else set LabelStatus.Text to "OK"
