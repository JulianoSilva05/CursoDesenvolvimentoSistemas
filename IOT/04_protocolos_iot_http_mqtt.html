Cliente/Servidor vs Publish/Subscribe

HTTP (cliente/servidor)

  • O cliente faz uma requisição (GET/POST)
  • O servidor responde (200, 404, 500...)
  • Bom para APIs, webhooks e dashboards

MQTT (publish/subscribe)

  • Dispositivos publicam em tópicos
  • Outros dispositivos/serviços assinam tópicos
  • Broker central (ex: Mosquitto) roteia mensagens

Erro comum: usar HTTP para telemetria em alta frequência e depois reclamar de lentidão. Telemetria contínua combina melhor com MQTT.

HTTP na prática: rotas e payload

Padrões úteis

  • GET para consultar estado
  • POST para enviar telemetria ou comando
  • JSON como padrão de dados

Exemplo de payload

POST /api/telemetria Content-Type: application/json {"deviceId":"esp32-01","ts":1712345678,"temp":26.3,"hum":62,"err":0}

App Inventor: o componente Web resolve o lado HTTP para você. O desafio é projetar o dado e tratar erros (timeout, sem internet, 500).

MQTT na prática: tópicos e boas práticas

Estrutura de tópicos

Use uma hierarquia que faça sentido:

iot/senai/lab1/esp32-01/telemetry iot/senai/lab1/esp32-01/cmd iot/senai/lab1/esp32-01/status

Evite tópicos genéricos demais (ex: dados).

QoS e retenção

  • QoS 0: mais rápido, pode perder mensagens
  • QoS 1: entrega pelo menos uma vez (pode duplicar)
  • Retain: broker guarda último valor (bom para status)

Projetar também é tratar duplicidade (id/ts).

Exemplo guiado: App envia HTTP para um webhook

Objetivo

Enviar uma leitura para um endpoint (pode ser um serviço de teste ou um servidor do professor).

  • Montar JSON
  • Enviar via POST
  • Tratar sucesso/erro

Pseudobloco

set Web1.Url to "https://SEU_ENDPOINT/api/telemetria" set Web1.RequestHeaders to make a list ("Content-Type: application/json") call Web1.PostText(text = json) when Web1.GotText do set LabelStatus.Text to join "OK: " responseCode when Web1.TimedOut do set LabelStatus.Text to "TIMEOUT"

Boa prática: se estiver offline, guardar em uma fila (TinyDB) e reenviar depois.

Atividade 2 (4h): Simular envio de telemetria via HTTP

Requisitos

  • Gerar telemetria simulada (temp/hum) no app
  • Montar JSON com deviceId e timestamp
  • Enviar por POST com o componente Web
  • Tratar: OK, erro, timeout (sem alert do navegador)

Desafio (extra)

  • Fila offline com TinyDB (guardar até enviar)
  • Botão “Reenviar pendências”
  • Log com últimos 20 envios
